WHAT IS pass@1?
  pass@1 = the fraction of problems where the model's single generated
  solution passes ALL test cases provided by the benchmark.
  Formula: correct_problems / total_problems × 100%
  n=1 because Azure Anthropic API does not support n>1 (multiple samples).

FAILURE TYPE GLOSSARY
  Each failing test case is tagged with one of these outcomes:

  WRONG_ANSWER
    Code ran successfully but produced incorrect output for the test input.

  RUNTIME_ERROR
    Code crashed during execution — e.g. index out of range, null pointer,
    uncaught exception, Python traceback, Go panic. The logic is buggy but
    compilation succeeded.

  COMPILATION_ERROR
    Code failed to compile/parse — syntax error or type error in the
    generated code.

  TIME_LIMIT_EXCEEDED
    Code took too long (exceeded the per-test CPU time limit). Usually caused
    by an O(n²) or worse algorithm on large inputs.

  MEMORY_LIMIT_EXCEEDED
    Code consumed more memory than allowed. Typically occurs with very large
    data structures or infinite recursion.

INFRASTRUCTURE NOTES
  ExecEval container settings used for this run:
    --cap-add SYS_RESOURCE   : allows prlimit syscall for setting resource limits
    --ulimit nproc=65535      : host-level thread limit removed
    --ulimit nofile=65535     : host-level file descriptor limit removed
    _as = -1 (unlimited)     : virtual memory limit removed (was 2GB default)
    Java/Kotlin nproc = 1024 : JVM spawns many internal threads; 256 was too low
    Go/JS nproc = 512        : sufficient for goroutines and Node event loop
    NUM_WORKERS = 32         : 32 parallel evaluation workers

  Previous runs had 0% for Go, Java, Kotlin, Javascript due to:
    - Missing --cap-add SYS_RESOURCE → prlimit failed → all code crashed
    - _as = 2GB → JVM virtual address space exceeded at startup
    - nproc = 23-25 → JVM internal threads hit limit immediately
  All three issues are now fixed. Remaining failures are genuine model errors.
